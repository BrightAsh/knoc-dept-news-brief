# 분석 파이프라인

목표는 언론 보도 전체를 부서에 던지는 것이 아니라, 기사 안에서 한국석유공사와 각 부서가 실제로 봐야 할 문장 또는 문단을 LLM이 고르게 하는 것입니다.

## 현재 원칙

- 키워드 기반 부서 분류는 사용하지 않습니다.
- LLM이 실제로 분류하지 못하면 결과를 만들지 않습니다.
- 부서명보다 부서 역할 설명과 한국석유공사의 역할을 우선합니다.
- 기사 하나가 여러 부서에 배정될 수 있습니다.
- 긴 기사 중 일부 문장/문단만 관련되면 해당 문장/문단을 근거로 저장합니다.

## 단계

1. 기사 수집

   `scripts/collect.mjs`가 RSS와 sitemap에서 특정 날짜 기사를 모읍니다. `--include-body` 옵션을 켜면 기사 본문 `<p>` 문단도 함께 저장합니다.

2. 기사 segment 생성

   `scripts/analyze.mjs`가 제목, 요약 문장, 본문 문단을 segment로 나눕니다. LLM은 기사 단위로 판단하되, 근거는 segment 단위로 반환합니다.

3. LLM 분류

   LLM 입력에는 다음 정보가 들어갑니다.

   - 한국석유공사의 역할과 분류 원칙: `config/knoc-context.json`
   - 22개 부서명과 부서 역할: `config/departments.json`
   - 기사 제목, 요약, 본문 segment

   LLM 출력은 다음을 포함합니다.

   - 한국석유공사 관점의 관련성 여부
   - 관련 부서 목록
   - 부서별 근거 segment id
   - 근거 원문 문장/문단
   - 판단 이유와 관련성 점수

4. 웹 UI 출력

   `briefs.json`에 `overall`과 `departments`를 저장합니다.

   - `overall`: LLM이 한국석유공사 관련 기사로 본 기사
   - `departments`: LLM이 부서 역할과 연결한 기사와 근거 문장/문단

## 기사 단위와 문장/문단 단위

운영 화면에서는 기사 단위가 기본 목록입니다. 다만 부서 배정의 근거는 문장/문단 단위로 저장합니다.

이유:

- 사용자는 보통 기사 링크 단위로 원문을 확인합니다.
- 긴 기사 안의 일부 문단만 특정 부서와 관련될 수 있습니다.
- 따라서 “기사 배정 + 근거 segment 표시”가 가장 현실적인 1차 구조입니다.

나중에 요약 기능을 추가할 때는 부서별 근거 segment만 모아 요약하면 됩니다.
